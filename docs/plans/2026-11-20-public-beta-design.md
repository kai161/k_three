# 晚安计划免费公测版设计

## 目标

让用户无需激活或付费即可完整体验七天，验证首次完成、持续回访和真实反馈，同时控制公开访问带来的模型成本。用户自行部署线上环境。

## 方案选择

1. **配置开关切换公测与付费模式（采用）**：公测七天全免费，保留旧付费能力供以后验证；需要同步修改后端权益和前端状态。
2. 直接删除激活与付费代码：实现略简单，但以后恢复付费验证需要重新开发，不采用。
3. 发布通用激活码：改动最少，但增加用户操作成本，也不能准确验证自然使用流程，不采用。

该方向已在用户确认“按建议先做公测版”时获得批准。

## 范围

- `PUBLIC_BETA=true` 时七天全部免费，状态返回 `publicBeta=true`，前端不再进入激活页。
- 公测默认每设备每 24 小时最多生成 3 次回应，可通过 `PUBLIC_DAILY_REPLY_LIMIT` 调整。
- 保留原有分钟级防刷；超过公测频率限制返回可恢复提示，不调用模型。
- `AI_DAILY_LIMIT` 控制单实例每日模型调用次数，耗尽或模型失败时返回明确标识的人工晚安卡片。
- 第 2 天完成后和第 7 天回顾页展示一个可选反馈问题；反馈最长 500 字，明确提示会保存，可跳过。
- 不加入账号、支付、社区、订阅、第三方统计或跨设备同步。

## 技术设计

- 为计划服务增加公测选项；付费模式原有两天免费与激活规则保持不变。
- 路由增加公测配置和每设备 24 小时限流，不放宽旧接口校验。
- 模型调用外增加按自然日计数的单实例预算装饰器；安全分流仍优先于预算和模型调用。
- PostgreSQL 新增 `feedback` 表，保存匿名设备摘要、对应第 2/7 天、反馈内容和时间；不保存原始倾诉。
- 前端根据 `publicBeta` 判断流程，不再依赖“第三天未激活”推断锁定。
- 公测反馈接口校验完成天数、内容长度和空内容，重复提交同一天反馈时更新该设备自己的反馈。

## 异常与兼容

- 公测关闭时，旧激活 API 和付费流程行为不变。
- 公测开启时，历史已激活设备继续原进度，不重置任何记录。
- 反馈失败不阻断七天完成或回顾；用户可重试或跳过。
- 限流和预算只影响新生成，不影响已完成内容、回顾和反馈。
- 预算计数为单实例内存状态，重启会重置；多实例部署时总额度约为每实例额度乘实例数，发布说明必须明确。

## 验证

- 单元测试覆盖公测第三天免费、旧付费模式仍锁定、反馈天数与长度、模型预算和安全分流。
- API 测试覆盖七天无激活、反馈保存与更新、公测频率限制和原始倾诉不入库。
- 浏览器完整走通七天，无激活页；验证第 2、7 天反馈、刷新恢复和高风险返回。
- 重复执行 Go、前端、PostgreSQL、冒烟及浏览器测试，覆盖率保持不低于 70%。

## 发布配置

- 公测：`PUBLIC_BETA=true`、`COOKIE_SECURE=true`、生产 `DATABASE_URL`、`AI_API_KEY`、`AI_DAILY_LIMIT`。
- 建议初始 `PUBLIC_DAILY_REPLY_LIMIT=3`、`AI_DAILY_LIMIT=100`，根据真实成本再调整。
- 健康检查使用 `/healthz`；不得将模型密钥、数据库连接或激活码写入前端。

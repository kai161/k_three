# 晚安计划产品走查与修复记录

## 体验范围

在 Chromium 的 390 × 844 移动端视口中，从首次访问开始，实际完成草稿刷新恢复、两天免费体验、激活码解锁、后五天仪式、七日回顾及高风险内容返回路径。服务连接真实 PostgreSQL；本轮未配置外部模型密钥，页面使用并明确标识人工晚安卡片。

## 已发现并修复

### 1. 高风险提示返回到空白回应页

- 影响：用户关闭求助提示后会看到没有内容的 AI 回应卡片，既困惑，也中断安全路径。
- 修复：返回按钮改为回到书写页，并保留本机草稿。
- 证据：Playwright 用例 `high-risk response returns to a safe writing path` 从失败变为通过。

### 2. 完成一天后仍显示已提交的旧文字

- 影响：进入下一天时，旧烦恼仍在输入框中，进度也不刷新，用户难以判断仪式是否真正完成。
- 修复：完成仪式后清除本机草稿；进入下一天时统一刷新进度和空白书写状态。
- 证据：主流程增加“输入框为空、已留下 1 个夜晚”断言，先复现失败，修复后通过。

### 3. 隐私说明忽略本机草稿

- 影响：“原文不保存”容易被理解为任何位置都不保存，与实际本机草稿恢复行为不一致。
- 修复：文案改为“服务器不存原文，草稿仅留在本机”。
- 证据：欢迎页截图确认新文案可见，数据库集成测试继续验证原始倾诉不入库。

### 4. 激活错误与书写错误混在一起

- 影响：“内容或激活码不正确”无法告诉付费用户到底哪里出错。
- 修复：激活码失败单独提示“激活码无效或已被使用，请核对后再试”。
- 证据：`TestAPIValidationAndStaticPage` 先验证旧提示失败，修复后通过。

### 5. 标题聚焦边框和辅助文字影响视觉体验

- 影响：自动聚焦产生与整体风格不协调的粗边框，浅灰辅助文字在移动端不够清晰。
- 修复：保留标题焦点管理但移除程序化焦点边框，加深辅助说明文字。
- 证据：欢迎、回应、激活和回顾四张稳定截图复核通过。

## 后续建议

### 上线前必须补齐

- 接入真实数字商品店铺链接，并在激活页展示实际价格；当前只有激活码输入，没有可点击的购买入口。
- 使用生产模型密钥验证真实模型的语气、稳定性、延迟和单次成本。OpenAI 兼容适配器已通过 `httptest` 真实 HTTP 测试，但本轮浏览器体验的是人工兜底，不应等同于真实 AI 验收。
- 配置 HTTPS、安全 Cookie、生产激活码、模型超时监控和备份。

### 首轮用户测试后再决定

- 是否严格限制每个自然日只能完成一天。当前是七个可顺序完成的仪式，先观察用户是否认可节奏，不在首版擅自增加日期限制。
- 是否增加账号和跨设备同步。当前匿名设备方案足够验证需求，但换设备后需要重新激活。
- 是否加入声音和更丰富的场景。先验证核心仪式与付费，不用素材投入掩盖需求不确定性。
